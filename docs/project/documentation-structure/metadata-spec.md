# Documentation metadata contract specification

- Status: implemented
- Date: 2026-07-27
- Owner: project documentation
- Evidence: verified
- Contract: living

- Parent goal:
  [DOCS-01](../goals/docs-01-documentation-structure-hardening.md)
- Program: [documentation structure hardening](README.md)

## Purpose

Replace free-form lifecycle prose with a small metadata contract that humans
and repository-local checks can interpret consistently.

## Canonical fields

Every specification, executable goal, audit, generated report and evidence
index must place these bullet-form fields immediately after its H1:

```md
- Status: <canonical status>
- Date: YYYY-MM-DD
- Owner: <documentation owner>
```

Add only when applicable:

```md
- Last verified: YYYY-MM-DD
- Evidence: not-run | partial | verified | manual-gate-open
- Parent goal: <repository-relative Markdown link>
- Related decisions: <one or more repository-relative Markdown links>
- Superseded by: <repository-relative Markdown link>
- Contract: living | closed
- Generated by: `npm run ...`
```

## Canonical status vocabulary

- `draft`: incomplete proposal, not executable.
- `specced`: accepted, bounded and ready for implementation.
- `active`: implementation or review currently owns repository work.
- `implemented`: required repository work is complete.
- `superseded`: replaced by a named later owner.
- `historical`: retained evidence with no current requirement authority.
- `generated`: deterministic report owned by a repository command.

Dates, browser coverage, disabled enforcement and adopter evidence must use
their own fields or prose. They must not create new status values.

## Requirements

1. Parse the first bounded metadata block without reading arbitrary body text.
2. Normalize all 101 existing specification status lines to the canonical
   bullet syntax and split dates/evidence/supersession from status.
3. Require `Parent goal` only for executable implementation specifications that
   participate in a goal program; historical specifications may retain their
   original relationship in prose.
4. Give generated reports `Status: generated` plus their exact generator.
5. Preserve Finnish or English document body language; metadata keys and enum
   values remain the English canonical contract.
6. Add deterministic checker diagnostics for a missing field, unknown status,
   duplicate field, malformed date, invalid owner or impossible combination.
7. Keep the checker read-only and independent of network, browser and current
   wall-clock time.

## Required impossible combinations

At minimum reject:

- `Status: generated` without `Generated by`;
- `Status: superseded` without `Superseded by`;
- `Status: implemented` with `Evidence: not-run` when the document claims its
  mandatory automated gate passed; and
- more than one `Status`, `Date` or `Owner` field.

## Non-goals

- Do not require front matter or an external documentation framework.
- Do not rewrite historical rationale or translate document bodies.
- Do not infer lifecycle from filenames such as `*-spec.md`.
- Do not mark manual screen-reader, public deployment or live-provider evidence
  verified without an actual dated run.

## Done when

- all in-scope documents use one parseable metadata form;
- the 77 free-form specification status values are replaced by the canonical
  vocabulary;
- lifecycle, date, evidence and supersession are separate facts;
- the checker has focused positive and negative fixtures; and
- documentation indexes can group files from metadata without body-text
  heuristics.

## Implementation evidence

- Every in-scope specification, goal, audit, generated report and evidence
  index now exposes canonical status, date and owner fields immediately after
  its H1.
- Technical specifications also expose an explicit living or closed contract
  class. Generated reports name their repository generator command.
- `scripts/documentation-check-core.ts` validates required fields, enums,
  dates, owners, duplicates and impossible generated/superseded/evidence
  combinations.
- Focused positive and negative metadata tests pass.
