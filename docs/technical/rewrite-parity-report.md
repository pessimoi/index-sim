# Rewrite vs legacy parity report

- Status: current audit snapshot
- Date: 2026-07-10
- Owner: technical docs
- Scope: calculation reliability of the Vite/React rewrite against the archived legacy `SimEngine.simulate()` baseline.

## Executive summary

The rewrite has strong parity evidence for the combat/equipment core numbers that users usually notice first: max hit, hit chance, average hit, DPS, effective DPS and special-attack fields. These are compared against all 18 legacy golden fixtures with `0.000001` numeric tolerance after 6-decimal rounding.

Trip, loot and supply parity is also good for every fixture currently wired into `src/tests/trip-loot-supply.test.ts`. Those tests cover GP/hr, net GP/hr, supply costs, prayer XP, trip bound, incoming damage, banking efficiency, top loot rows, cannon occupancy and cannonball supply for melee, ranged and magic cases, with focused rewrite coverage for scarce/respawn caps and inventory reserve details.

Loot UI evidence now covers the visible nested workflow slice: view-model tests verify value composition totals, top-contributor/tail grouping, full nested `_expand` row normalization, action-impact metadata, inventory-displaced row labels and browser-local price-history context without changing loot math, while Playwright smoke opens Loot, checks composition, expands action impact detail, changes a drop action, expands a nested herb detail table and verifies local history context from accepted browser history.

XP/hr now has direct fixture evidence for 17 current-behavior cases through `src/tests/xp-parity.test.ts`, including cannon ranged XP as a separate effective XP row, Prayer XP from current bury loot rows and Magic alch XP from tracked in-trip alch casts. `totalXpPerHour` is compared for every non-recoil fixture by summing the rewrite-owned XP source rows, and UI view-model summary numbers are snapshot-compared against default melee, ranged safespot and cannon-enabled ranged paths. The Stats pane now surfaces combat roll detail and XP routing rows from the view-model: combat roll detail shows normal-attack effective accuracy/damage, attack/defence rolls, hit chance, max hit, average hit, speed/cycle and current-result TTK/kills/hr/GP/kill with fallback `-` values for unavailable data, while XP routing includes player combat XP, cannon ranged XP when active, skill-specific combat rows and modeled Prayer/Magic-alch rows without partial/not-modeled status when the data is available from the domain result. Playwright also snapshots browser-rendered dense table numeric cells for release-path rows covering default melee, melee alch-relevant, ranged safespot, ranged cannon with negative net GP/hr, magic safespot and custom/loot-settings marker paths, plus metric-strip acceptance numbers for those target selections, loot action override, manual food/prayer trip, imported PriceSet, mocked market sync and compatible legacy import paths. The all-fixture browser-display case additionally reloads all 18 golden setups and compares all ten visible metric-strip values with the source-backed view-model result. The Cannon tab has browser evidence for sparse-link/reset behavior and expanded output metrics, and the Stats pane has smoke evidence for combat roll detail, XP routing, Trip/banking summary and the hit distribution histogram. The current 53/53 browser gate has no active numeric mismatch; its initial focused all-fixture run found and closed a scheduled-price/generated-fallback wiring mismatch without changing combat formulas or golden fixtures. The ring-of-recoil XP/hr difference is an accepted intentional rewrite delta in [D-031](../project/decisions.md): legacy remains comparison evidence, but rewrite combat XP is calculated from direct player combat damage and is not reduced by trip-layer recoil damage. The main remaining reliability caveats are further combat roll edge-case parity if required, optional planner legacy numeric parity if a legacy-clone line is explicitly requested, live upstream parity for market/hiscores, visual regression if later required and deeper legacy `localStorage` migration decisions beyond the accepted V1 boundary.

Planner V1 is accepted on the rewrite replacement line as of the 2026-07-08 Planner follow-up. Its acceptance evidence is deterministic rewrite-domain golden coverage for melee weapon unlock, ranged bow unlock, magic spell unlock and boosted sustained training, plus visible Planner smoke coverage for metric/current-XP/target/skill-lock/avg-over-session/gear-pool/Recompute/warning output. The Planner UI state is versioned separately from setup state and adapts into `src/domain/planner` options without adding Planner fields to `SimulationRequest`; the gear pool editor is constrained to active `GameDataSnapshot` items from the accepted non-hypothetical default planner pool. The implemented [legacy Planner parity audit](legacy-planner-parity-spec.md) adds 16 bounded cases and 32 reference-context/current-product comparisons. Training order and bounded control behavior match throughout; the classified [current report](../project/planner-parity/current.md) records 29 accepted rewrite warning/scoring/transition deltas and three Revision 274 source-data deltas, with zero rewrite gaps or review blockers. This does not claim exact numeric equivalence to legacy `planner-core.js` or decide the authoritative generated item requirement source. D-047 keeps future/hypothetical gear out of V1, D-048 keeps legacy `sim_planner_v1` state review-only/not migrated for V1 and D-051 keeps the manual requirement fallback for legacy/missing-generated-data snapshots in V1.

Combat setup, Stats analysis, Special attacks and Result summary are accepted for the V1 replacement line as of the 2026-07-08 Goal 1 follow-up. The accepted line is visible workflow parity in the rewrite architecture: combat-style controls route to the matching loadout tab, per-style loadout state is restored from rewrite setup state, Stats source breakdown/XP routing/result detail stays read-only view-model output, supported melee/ranged special attacks surface existing domain metrics, magic and DBA states emit no DPS-special request, and Result summary keeps its existing `Valmis` behavior. The accepted line is the visible all-monster dense workflow in the rewrite architecture: full sortable table, monster/drop filters, row target selection, active and forced-visible current target markers, rewrite-owned relevance persistence, custom setup and per-monster loot-setting markers, visible-row scale indicators, contained mobile/tablet overflow and representative browser-rendered dense numeric evidence. This does not decide exact archived legacy `potRec` numerical parity, change prayer potion modeling, choose live/provider/canonical data policy or add new runtime/backend state.

Legacy saved state migration is accepted for the V1 replacement line after the D-042 implementation and later migration extensions. The visible Import/Keep/Clear workflow classifies every known legacy key, shows metadata-only import/skip/review outcomes and imports compatible setup, custom setup, cannon, Duel snapshot, hiscores, current-price, hidden-tier, compare and loot-preference data into validated rewrite-owned state. Compatible `sim_input_v3.duelSetups` rows inherit the legacy player context, map only supported setup fields, keep existing rewrite snapshots, reject computed rows and obey the shared 12-entry cap. The optional Duel monster matrix is now implemented as an on-demand view over the same current simulation path: it compares live plus saved setups across the generated monster catalog without persisting calculated output or changing snapshot migration. Import and Keep preserve legacy keys, confirmed Clear removes only the exact known-key list, and invalid, oversized, unsafe, unknown or ambiguous values remain non-fatal with sanitized reasons. D-048 keeps `sim_planner_v1` review-only/not migrated, and D-049 keeps full legacy price-history keys review-only/not migrated.

## Status meanings

- `pass`: Direct rewrite-vs-legacy parity exists for the relevant numeric fields in the current fixture scope.
- `accepted`: Rewrite-domain acceptance evidence exists for the replacement line, while legacy numeric parity remains an explicit non-blocking decision boundary.
- `partial`: Some evidence exists, but coverage is incomplete, indirect or not UI-level.
- `fail`: A known mismatch is currently proven by tests or audit evidence.
- `not ported`: No maintained rewrite path exists yet for the behavior.

## Fixture coverage

The legacy baseline currently has 18 cases:

- 8 melee cases covering rune scimitar, dragon weapons, poison, special attacks, recoil, alch, food-limited trips, low-value loot and dragons.
- 5 ranged cases covering bow, thrown weapon, safespot, ammo recovery/no recovery, special attack and a cannon fixture input.
- 5 magic cases covering bolt/wave/god spells, charge, alch, rune cost, poison and safespot behavior.

Trip/loot/supply parity currently covers all 18 cases, including the cannon fixture's occupancy/overlay behavior and cannonball supply accounting.

XP parity currently covers 17 of these 18 cases. The remaining case is an accepted intentional rewrite delta:

- `melee_ring_recoil_fire_giant_food_trip`: diagnostic coverage shows the trip/KPH/recoil damage fields match legacy, but XP/hr does not. Legacy scales combat XP by an XP direct fraction of about `0.971821` because recoil contributes to kill DPS but grants no XP. D-031 accepts the rewrite behavior: recoil remains trip-layer damage/cost evidence and legacy remains comparison evidence, while combat XP stays attributed to direct player combat damage.
