# Rewrite vs legacy parity report

- Status: current audit snapshot
- Date: 2026-07-06
- Owner: technical docs
- Scope: calculation reliability of the Vite/React rewrite against the archived legacy `SimEngine.simulate()` baseline.

## Executive summary

The rewrite has strong parity evidence for the combat/equipment core numbers that users usually notice first: max hit, hit chance, average hit, DPS, effective DPS and special-attack fields. These are compared against all 18 legacy golden fixtures with `0.000001` numeric tolerance after 6-decimal rounding.

Trip, loot and supply parity is also good for every fixture currently wired into `src/tests/trip-loot-supply.test.ts`. Those tests cover GP/hr, net GP/hr, supply costs, prayer XP, trip bound, incoming damage, banking efficiency, top loot rows, cannon occupancy and cannonball supply for melee, ranged and magic cases, with focused rewrite coverage for scarce/respawn caps and inventory reserve details.

Loot UI evidence now covers the visible nested workflow slice: view-model tests verify value composition totals, top-contributor/tail grouping, full nested `_expand` row normalization, action-impact metadata, inventory-displaced row labels and browser-local price-history context without changing loot math, while Playwright smoke opens Loot, checks composition, expands action impact detail, changes a drop action, expands a nested herb detail table and verifies local history context from accepted browser history.

XP/hr now has direct fixture evidence for 17 current-behavior cases through `src/tests/xp-parity.test.ts`, including cannon ranged XP as a separate effective XP row, and UI view-model summary numbers are snapshot-compared against default melee, ranged safespot and cannon-enabled ranged paths. Playwright also snapshots browser-rendered dense table numeric cells for representative default melee Hill Giant, settled ranged Greater Demon and cannon-enabled ranged Dagannoth rows, plus metric-strip acceptance numbers for default melee, ranged safespot, cannon, loot action override, manual food/prayer trip, imported PriceSet, mocked market sync and compatible legacy import paths. The Cannon tab now has browser evidence for sparse-link/reset behavior and expanded output metrics. The ring-of-recoil XP/hr difference is now an accepted intentional rewrite delta in [D-031](../project/decisions.md): legacy remains comparison evidence, but rewrite combat XP is calculated from direct player combat damage and is not reduced by trip-layer recoil damage. The main remaining reliability caveats are full-fixture browser-display expansion if required, optional planner legacy numeric parity if a legacy-clone line is explicitly requested, live upstream parity for market/hiscores and legacy `localStorage` migration.

Planner V1 is accepted on the rewrite replacement line. Its acceptance evidence is deterministic rewrite-domain golden coverage for melee weapon unlock, ranged bow unlock, magic spell unlock and boosted sustained melee training, plus visible Planner smoke coverage for metric/current-XP/target/skill-lock/avg-over-session/gear-pool/Recompute/warning output. This does not claim numeric equivalence to legacy `planner-core.js`; legacy planner numeric parity remains an open decision boundary rather than a blocker for the accepted V1 rewrite Planner.

## Status meanings

- `pass`: Direct rewrite-vs-legacy parity exists for the relevant numeric fields in the current fixture scope.
- `accepted`: Rewrite-domain acceptance evidence exists for the replacement line, while legacy numeric parity remains an explicit non-blocking decision boundary.
- `partial`: Some evidence exists, but coverage is incomplete, indirect or not UI-level.
- `fail`: A known mismatch is currently proven by tests or audit evidence.
- `not ported`: No maintained rewrite path exists yet for the behavior.

No committed failing parity tests are left in this audit. The main gaps are `partial` or `not ported`; Planner is `accepted` on the rewrite replacement line without legacy numeric parity, and the ring-of-recoil XP/hr fixture is an explicit accepted intentional delta with diagnostic coverage.

## Fixture coverage

The legacy baseline currently has 18 cases:

- 8 melee cases covering rune scimitar, dragon weapons, poison, special attacks, recoil, alch, food-limited trips, low-value loot and dragons.
- 5 ranged cases covering bow, thrown weapon, safespot, ammo recovery/no recovery, special attack and a cannon fixture input.
- 5 magic cases covering bolt/wave/god spells, charge, alch, rune cost, poison and safespot behavior.

Trip/loot/supply parity currently covers all 18 cases, including the cannon fixture's occupancy/overlay behavior and cannonball supply accounting.

XP parity currently covers 17 of these 18 cases. The remaining case is an accepted intentional rewrite delta:

- `melee_ring_recoil_fire_giant_food_trip`: diagnostic coverage shows the trip/KPH/recoil damage fields match legacy, but XP/hr does not. Legacy scales combat XP by an XP direct fraction of about `0.971821` because recoil contributes to kill DPS but grants no XP. D-031 accepts the rewrite behavior: recoil remains trip-layer damage/cost evidence and legacy remains comparison evidence, while combat XP stays attributed to direct player combat damage.

## Known intentional baseline behavior

Current golden fixtures preserve legacy behavior before bug fixes. These are not accepted permanent product decisions:

- Dragon halberd special still follows the legacy small-target behavior because NPC size data is missing.
- Ranged, magic and halberd auto-safespot behavior is preserved in fixtures.
- Ring of Wealth scope follows current `GameData.adjustForRoW` behavior.
- Known market and legacy planner bugs are outside the `SimEngine.simulate()` golden fixture set.

See [../project/bug-triage.md](../project/bug-triage.md) for the current list.

## Release blockers before full replacement

- Extend UI-level numeric regression checks beyond the current release-path snapshots if all-fixture browser-display parity is required.
- Add legacy planner numeric parity fixtures only if a user explicitly chooses the legacy-clone line instead of the accepted rewrite replacement line.
- Decide whether the review-only legacy `localStorage` areas should get deeper migration, remain explicit reset-only flows or stay legacy-only: planner state, custom setup migration, loot prefs, compare/cannon maps, hidden tiers and full legacy price history. The current accepted boundary for `sim_planner_v1` is detect/review-only without import.
- Replace the raw legacy data bootstrap with an authoritative generated `GameDataSnapshot` before deleting legacy data sources.
- Choose the authoritative market and hiscores upstreams, production runtime/hosting and provider wiring before claiming live upstream parity for market or hiscores.

## Security and privacy notes

This report uses committed fixtures and source-controlled tests only. It does not use player names, browser `localStorage`, live hiscores, live market requests, secrets or machine-local data.

The legacy archive may still contain references to `/api/*`, `run_sim.py`, CDN scripts and browser globals. Those are not part of the root Vite production path, and they are not parity evidence for the rewrite UI. The production rewrite service copy is driven by same-origin status endpoints and the disabled default provider rather than local `run_sim.py` instructions.

## Recommended next parity goals

1. Extend browser-rendered numeric snapshots if all-fixture UI formatting/display parity is required beyond the current release-path snapshots.
2. Add legacy planner numeric parity only if a user explicitly chooses the legacy-clone line.
3. Decide whether review-only legacy planner, custom setup, loot prefs, compare state, cannon map, hidden tiers and full price-history keys should be migrated or intentionally left behind.
