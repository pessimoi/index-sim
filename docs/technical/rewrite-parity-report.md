# Rewrite vs legacy parity report

- Status: current audit snapshot
- Date: 2026-07-08
- Owner: technical docs
- Scope: calculation reliability of the Vite/React rewrite against the archived legacy `SimEngine.simulate()` baseline.

## Executive summary

The rewrite has strong parity evidence for the combat/equipment core numbers that users usually notice first: max hit, hit chance, average hit, DPS, effective DPS and special-attack fields. These are compared against all 18 legacy golden fixtures with `0.000001` numeric tolerance after 6-decimal rounding.

Trip, loot and supply parity is also good for every fixture currently wired into `src/tests/trip-loot-supply.test.ts`. Those tests cover GP/hr, net GP/hr, supply costs, prayer XP, trip bound, incoming damage, banking efficiency, top loot rows, cannon occupancy and cannonball supply for melee, ranged and magic cases, with focused rewrite coverage for scarce/respawn caps and inventory reserve details.

Loot UI evidence now covers the visible nested workflow slice: view-model tests verify value composition totals, top-contributor/tail grouping, full nested `_expand` row normalization, action-impact metadata, inventory-displaced row labels and browser-local price-history context without changing loot math, while Playwright smoke opens Loot, checks composition, expands action impact detail, changes a drop action, expands a nested herb detail table and verifies local history context from accepted browser history.

XP/hr now has direct fixture evidence for 17 current-behavior cases through `src/tests/xp-parity.test.ts`, including cannon ranged XP as a separate effective XP row, Prayer XP from current bury loot rows and Magic alch XP from tracked in-trip alch casts. `totalXpPerHour` is compared for every non-recoil fixture by summing the rewrite-owned XP source rows, and UI view-model summary numbers are snapshot-compared against default melee, ranged safespot and cannon-enabled ranged paths. The Stats pane now surfaces combat roll detail and XP routing rows from the view-model: combat roll detail shows normal-attack effective accuracy/damage, attack/defence rolls, hit chance, max hit, average hit, speed/cycle and current-result TTK/kills/hr/GP/kill with fallback `-` values for unavailable data, while XP routing includes player combat XP, cannon ranged XP when active, skill-specific combat rows and modeled Prayer/Magic-alch rows without partial/not-modeled status when the data is available from the domain result. Playwright also snapshots browser-rendered dense table numeric cells for release-path rows covering default melee, melee alch-relevant, ranged safespot, ranged cannon with negative net GP/hr, magic safespot and custom/loot-settings marker paths, plus metric-strip acceptance numbers for those target selections, loot action override, manual food/prayer trip, imported PriceSet, mocked market sync and compatible legacy import paths. The Cannon tab now has browser evidence for sparse-link/reset behavior and expanded output metrics, and the Stats pane has smoke evidence for combat roll detail, XP routing, Trip/banking summary and the hit distribution histogram. The 2026-07-08 numeric snapshot audit found no active Playwright numeric mismatch after the current 51/51 browser gate, kept the historical dense release-path and loot/trip numeric rows classified as timing/actionability failures, and changed no numeric expectations, source formulas or golden fixtures. The ring-of-recoil XP/hr difference is now an accepted intentional rewrite delta in [D-031](../project/decisions.md): legacy remains comparison evidence, but rewrite combat XP is calculated from direct player combat damage and is not reduced by trip-layer recoil damage. The main remaining reliability caveats are further combat roll edge-case parity if required, full-fixture browser-display expansion if required, optional planner legacy numeric parity if a legacy-clone line is explicitly requested, live upstream parity for market/hiscores and deeper legacy `localStorage` migration decisions beyond the accepted V1 boundary.

Planner V1 is accepted on the rewrite replacement line as of the 2026-07-08 Planner follow-up. Its acceptance evidence is deterministic rewrite-domain golden coverage for melee weapon unlock, ranged bow unlock, magic spell unlock and boosted sustained training, plus visible Planner smoke coverage for metric/current-XP/target/skill-lock/avg-over-session/gear-pool/Recompute/warning output. The Planner UI state is versioned separately from setup state and adapts into `src/domain/planner` options without adding Planner fields to `SimulationRequest`; the gear pool editor is constrained to active `GameDataSnapshot` items from the accepted non-hypothetical default planner pool. This does not claim numeric equivalence to legacy `planner-core.js`, import `sim_planner_v1`, choose future/hypothetical gear policy or decide the authoritative generated item requirement source.
